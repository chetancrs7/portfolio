## Overview

This case study documents an **experimental research system**, not a production sentiment API. The goal was to test whether pairing two very different classifiers — a spline-based semantic model and a gradient-boosted linguistic model — behind a learned gate would beat either one alone on binary tweet sentiment, and to keep the architecture modular enough that each pathway's contribution could be measured on its own.

The short answer is the interesting part: the semantic expert did almost all of the work, and the learned fusion added no measurable accuracy over it. That negative result — and the diagnostics that explain it — is the substance of the project.

<Callout type="result">
  On the held-out Sentiment140 test split, the fused model reached **0.875
  accuracy**, **0.875 macro-F1**, and **0.947 AUC**, with an expected
  calibration error of **0.0065** after temperature scaling. The standalone KAN
  semantic expert reached the same 0.875 accuracy — the learned gate matched its
  stronger expert to three decimal places rather than improving on it.
</Callout>

> **Engineering question.** Can a hybrid model combine contextual semantic
> representations with explicit linguistic structure while staying modular,
> measurable, calibrated, and reasonably decomposable — and does the learned
> fusion actually exploit the two experts' differences?

**Research framing** asks whether hybrid expert fusion improves sentiment
classification. **Engineering framing** asks whether the system can be built so
that the contribution of each pathway is inspectable in isolation. The project
answers the second cleanly and the first with a qualified _no_ for this dataset.

## Problem

Sentiment on short, noisy text pulls in two directions. Lexical and structural
signals — negation, intensifiers, punctuation, capitalisation, emoji polarity —
are cheap, explicit, and easy to inspect, but they are brittle when meaning
depends on context. Transformer embeddings capture that context, but a raw
768-dimensional vector is opaque: it is hard to say _why_ a prediction was made,
and a single dense representation gives no natural place to reason about the
decision.

The project treats this as a motivation for an experiment rather than a solved
problem. If contextual meaning and explicit surface structure are genuinely
different views of a tweet, then two specialists — one per view — plus a gate
that learns _who to trust per sample_ should beat a single model that has to do
both jobs at once. That is a testable claim, and the architecture below exists
to test it.

## Architecture

The system is a **parallel, decision-level ensemble**. A tweet is encoded once
by DeBERTa; the embedding then feeds two independent experts whose class
probabilities are combined by a small learned gate.

The design splits cleanly into three stages:

- **Stage 1 — Semantic representation.** `microsoft/deberta-v3-base` produces a
  768-dimensional contextual embedding per tweet. This vector is the single
  shared input to both downstream experts.
- **Stage 2 — Parallel experts.** A Kolmogorov–Arnold Network (KAN) learns
  nonlinear semantic relationships directly from the embedding. In parallel,
  XGBoost operates on 50 engineered linguistic features extracted from the raw
  text — it never sees the embedding.
- **Stage 3 — Adaptive fusion.** A gating network emits a per-sample weight
  `alpha` and the final prediction is `alpha * P_kan + (1 - alpha) * P_xgb`.

## Semantic Expert — KAN

A Kolmogorov–Arnold Network replaces a linear layer's fixed weight matrix with a
matrix of _learnable univariate functions_. An edge from input `i` to output `j`
computes `phi_ij(x_i) = scale_base * base(x_i) + scale_sp * spline_ij(x_i)`, and
each output neuron sums the edge functions feeding into it: `y_j = sum_i
phi_ij(x_i)`. Gradients from the downstream loss flow straight into the spline
coefficients, so the _shape_ of every edge function is learned like any other
weight — and each spline's grid is periodically refit to the quantiles of the
activations that actually flow through it.

The pathway is deliberately **shallow** — three hidden layers of width 256, 128,
and 64 — and each layer is named for the role it plays, with the spline family
chosen to match that role:

```python title="src/models/kan/model.py" showLineNumbers {8-14}
class KANSentimentClassifier(nn.Module):
    """Four adaptive-spline layers over a fixed 768-d DeBERTa embedding."""

    def __init__(self, input_dim=768, hidden_dims=(256, 128, 64), n_classes=2,
                 grid_size=5, spline_order=3, grid_range=(-2.0, 2.0)):
        super().__init__()
        semantic_dim, context_dim, distortion_dim = hidden_dims
        # Each stage uses the spline family its role implies.
        self.semantic_compression = SemanticCompressionLayer(input_dim, semantic_dim, ...)    # B-spline
        self.context_interaction  = ContextInteractionLayer(semantic_dim, context_dim, ...)   # B-spline
        self.sentiment_distortion = SentimentDistortionLayer(context_dim, distortion_dim, ...) # thin-plate
        self.emotion_hotspot      = EmotionHotspotLayer(distortion_dim, n_classes, ...)        # Gaussian RBF

    def forward(self, x):
        x = self.semantic_compression(x)
        x = self.context_interaction(x)
        x = self.sentiment_distortion(x)
        return self.emotion_hotspot(x)  # class logits
```

The shallow, named structure is an interpretability decision. Replacing an
opaque 768-dimensional transform with four small, role-labelled stages is
**designed to improve decomposability** — the learned spline activations can be
extracted and visualised per stage — but it is not a guarantee of causal
explanation, and this case study does not claim one. Two extras keep the splines
honest: grid _adaptation_ moves knots and radial centres to the data quantiles
during training, and optional grid _refinement_ grows spline resolution
mid-training (e.g. `--grid-refine "40:8,80:12"`). Because the thin-plate kernel
is unbounded, the expert is trained with gradient clipping.

## Structural Expert — XGBoost

XGBoost is the counterweight: a strong learner over heterogeneous, engineered
features whose meanings are known in advance. It was chosen because tree
ensembles model nonlinear interactions between mixed-scale features without
feature scaling, are a strong baseline on tabular inputs, and support
straightforward feature-importance and SHAP analysis. That is a fit for _this_
feature set — not a claim that trees dominate tabular problems in general.

The extractor turns each tweet into a fixed-width vector of 50 interpretable
signals, grouped by what they capture:

- **Negation** — negation-cue counts and ratios, plus spaCy dependency-parse
  negation relations (`dep_neg_count`).
- **Intensity** — weighted intensifier/downtoner scores, ALL-CAPS frequency and
  ratio, and punctuation counts (exclamation, question, ellipsis) and density.
- **Emoji & lexical sentiment** — emoji and emoticon polarity sums and density,
  VADER sentence scores (compound / pos / neg / neu), elongation-aware lexicon
  hit ratios ("goooood" resolves to "good"), and VADER polarity over camel-split
  hashtag tokens (`#FollowFriday` → "follow friday").
- **Linguistic structure** — universal POS-tag distribution, dependency-parse
  statistics (amod/advmod relation counts, max and mean tree depth), and a
  subjectivity ratio.
- **Writing style** — stretched-word ("sooooo") counts and a sarcasm heuristic
  that includes scare-quote usage next to positive sentiment.

Every group degrades gracefully: if spaCy or a lexicon is unavailable the
columns are zero-filled rather than dropped, so the feature width is stable
across machines. Hyperparameters were tuned with Optuna against validation
macro-F1:

```yaml title="conf/model/kan_xgboost.yaml" showLineNumbers
kan:
  hidden_dims: [256, 128, 64] # widths of the three hidden spline layers
  grid_size: 5 # B-spline intervals / radial-centre count
  spline_order: 3 # B-spline polynomial degree (radial layers ignore it)
  grid_range: [-2.0, 2.0] # re-placed at data quantiles during training

xgboost:
  n_estimators: 750
  max_depth: 7
  learning_rate: 0.2486 # best Optuna trial (validation macro-F1)
  subsample: 0.9352
  colsample_bytree: 0.7256

fusion:
  hidden_dim: 64
  dropout: 0.2
```

## Adaptive Fusion

The gate is a small MLP — `Linear → LayerNorm → ReLU → Dropout → Linear →
Sigmoid` — that reads meta-features derived from the two experts' outputs
(confidences, their difference, entropy, and a residual histogram) and emits a
single per-sample weight `alpha` in `[0, 1]`. `alpha` is the trust placed in the
KAN; `1 − alpha` goes to XGBoost. Because a mixture of two valid probability
distributions is itself a valid distribution, the fused output needs no
renormalisation and the gate can be trained directly on the log of the mixture.

```python title="src/fusion/fusion_model.py" showLineNumbers {3-6,11-13}
@staticmethod
def fuse(alpha, kan_probs, xgb_probs):
    # Convex combination of two distributions -> still a distribution.
    if alpha.dim() == 1:
        alpha = alpha.unsqueeze(1)
    return alpha * kan_probs + (1.0 - alpha) * xgb_probs


def fused_cross_entropy(alpha, kan_probs, xgb_probs, labels):
    fused = FusionGate.fuse(alpha, kan_probs, xgb_probs)
    log_probs = torch.log(fused.clamp_min(1e-8))
    return F.nll_loss(log_probs, labels)  # gate trained on the mixture itself
```

The hypothesis was that different experts win on different examples — the KAN on
context-dependent meaning, XGBoost on explicit surface cues — so a per-sample
gate should route to whichever expert is stronger and unlock a gain neither
reaches alone. A post-fusion uncertainty-aware fallback (thresholds calibrated on
a held-out split, detector fit on train embeddings to avoid leakage) can further
route or soften low-confidence, high-disagreement, or out-of-distribution cases.

<Callout type="note">
  The gate's learned mean `alpha ≈ 0.98`. Read carefully: this does **not** mean
  the KAN is always right. It means the learned fusion behaviour was dominated
  by the semantic pathway — the gate leaned on the KAN for almost the entire
  mixture and gave the structural expert little weight.
</Callout>

Sentiment140 is a distant-supervision corpus: labels come from emoticons present
at collection time, which is a known source of noise. Text cleaning preserves
emoji as their own tokens so their polarity survives into the embedding. The
XGBoost expert and baselines are trained and evaluated on the full split; the KAN
and fusion stages run on a stratified, class-balanced subsample for CPU-friendly
training, then evaluate on the held-out test data.

### Reproducibility

hyperparameter lives in versioned YAML under `conf/` and any value can be
overridden or swept from the command line (`python src/train.py -m
model.xgboost.max_depth=3,5,7`). Requires Python 3.11+; KAN training curves and

## What Didn't Work

The fusion architecture did not produce the improvement it was built to produce.

<Callout type="warning">
  Fusion accuracy (0.875) equals the standalone KAN accuracy (0.875). With a
  mean gate weight of `alpha ≈ 0.98`, the ensemble leaned almost entirely on the
  semantic expert, and the structural expert's contribution to the final
  decision was negligible. The two experts were not complementary enough — as
  combined by this learned gate — to move the number.
</Callout>

This is the most valuable engineering finding in the project, so it is worth
stating plainly rather than dressing up. A gate that converges to `alpha ≈ 0.98`
is telling you that, sample by sample, mixing in the weaker structural expert
rarely helped — either because the KAN was already right, or because when it was
wrong the structural expert was usually wrong too.

The complementarity suite separates those cases. Its **oracle-ensemble
accuracy** — the accuracy an _ideal_ gate would reach if it always deferred to
whichever expert happened to be correct — sits meaningfully above the learned
fusion, at roughly **0.92**.

The gap between the learned fusion (0.875) and the oracle (≈ 0.92) is the point.
It shows the experts _do_ contain some complementary information — there is a set
of tweets XGBoost gets right that the KAN misses — but the learned gate captured
essentially none of it. This is a diagnosis of the **gating mechanism**, not
proof that a better ensemble is impossible; it says the failure is in _how trust
was learned_, not (only) in the experts themselves. It also says nothing beyond
what the experiment supports: the oracle is an upper bound under perfect
selection, not an achievable target.

## Calibration & Reliability

Accuracy is only half of a probabilistic classifier's job; the other half is
whether its confidence means anything. Calibration is measured with **expected
calibration error (ECE)** — the average gap between confidence and actual
accuracy across confidence bins.

Calibration is applied with **per-expert temperature scaling**: a single scalar
`T` per expert, fit by minimising negative log-likelihood on a held-out split —
never on the test set. Temperature scaling is monotonic, so it never changes an
expert's hard predictions; it only re-scales confidence, which both feeds the
gate honest signals and shifts the confidence-weighted mixture. The resulting
**ECE of 0.0065** means the fused confidences track observed accuracy closely.
That is a good number for this setup, not a claim of perfect calibration —
in-distribution reliability does not imply the same on other domains.

## Interpretability

Interpretability here is **architectural and decompositional**, and the project
is careful not to overstate it.

- **Named semantic stages.** The KAN's four role-named layers, and the ability
  to extract and visualise each layer's learned spline activations, make the
  semantic pathway more decomposable than a single dense transform.
- **Meaningful structural features.** Every XGBoost input has a known meaning —
  negation, emoji polarity, intensification, subjectivity — so `TreeExplainer`
  gives _exact_ Shapley attributions over inspectable quantities, not latent
  dimensions.
- **An explainable gate.** SHAP on the gate showed its trust `alpha` is driven
  mainly by expert confidence, the confidence difference, and entropy — which is
  consistent with a gate that mostly follows the more confident expert.

None of this is a causal explanation of _why a tweet is positive_. Decomposition
makes the model easier to reason about; it does not certify the reasoning.

## Tradeoffs & Limitations

Each major decision bought something and cost something.

| Decision                  | Benefit                                               | Cost                                                           |
| ------------------------- | ----------------------------------------------------- | -------------------------------------------------------------- |
| DeBERTa-v3 embeddings     | Rich contextual representation shared by both experts | High-dimensional, opaque input                                 |
| KAN semantic expert       | Strong accuracy; more decomposable than a dense MLP   | Extra complexity; unbounded TPS kernel needs gradient clipping |
| XGBoost structural expert | Strong tabular learner over inspectable features      | Feature-engineering overhead for little final-decision weight  |
| Learned fusion gate       | Adaptive per-sample expert weighting                  | Added machinery with no measurable accuracy gain here          |

## Next Iteration

The oracle gap points the follow-up work at the _gate_, not just the experts:

1. **Increase expert complementarity** rather than raw expert strength — a
   stronger KAN alone widens the fusion's irrelevance.
2. **Change the fusion objective** to reward disagreement resolution, not just
   fused likelihood.
3. **Train the gate against expert disagreement** so it is optimised on the
   samples where the choice actually matters.
4. **Add uncertainty-aware gating** that leans on the fallback signals
   (entropy, OOD score) during training, not only at inference.
5. **Analyse per-class and per-category expert wins** to see where XGBoost
   genuinely rescues the KAN.
6. **Test whether structural features add unique information** at all, via an
   ablation of the engineered feature set.
7. **Evaluate across additional sentiment datasets** to check domain transfer.
8. **Compare against full DeBERTa fine-tuning** as a stronger upper baseline.

## What I Learned

- A strong single expert can make fusion pointless: if one model already
  captures most of the signal, a gate has little left to gain.
- **Complementarity matters more than model diversity.** Two very different
  architectures are not automatically complementary where it counts.
- **Oracle-vs-learned fusion is a sharp diagnostic.** The gap between them
  localised the failure to the gating mechanism, which no single accuracy number
  would have revealed.
- **Calibration deserves its own evaluation.** ECE, measured and improved
  separately from accuracy, is what makes the confidences usable.
- **Interpretability has to be designed into the representation** — named stages
  and meaningful features — not recovered afterwards, and even then it is
  decomposition, not causation.

A negative fusion result, measured honestly and explained with the right
diagnostics, is a more useful engineering artifact than a hybrid that "wins" for
reasons no one can name.
